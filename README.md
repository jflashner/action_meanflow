# One-step world models: MeanFlow vs. diffusion in DIAMOND

This fork of [DIAMOND](https://github.com/eloialonso/diamond) swaps its EDM diffusion loss for MeanFlow, and for
the other few-step objectives MeanFlow should be compared to. All of them use **the same U-Net, data, optimizer and
number of updates**, so that only the training objective and the sampler differ. The question it tests: can a
1-step model trained without a teacher match the quality of a few-step diffusion model on game transitions,
especially on Boxing, where the opponent is stochastic?

The original DIAMOND README follows below. Everything in it still works: the default config is unchanged, and the
pretrained DIAMOND checkpoints still load.

## Methods (`agent/denoiser=...`)

| Config | Method | Sampling | Code |
|---|---|---|---|
| `edm` | DIAMOND's EDM denoiser (baseline) | 1 or 3 Euler steps | `src/models/diffusion/denoiser.py` |
| `fm` | Flow matching / rectified flow | 1–8 Euler steps | `src/models/diffusion/flow_denoiser.py` |
| `shortcut` | Shortcut model (Frans et al., 2024): step-size conditioning + self-consistency | 1–8 steps | same |
| `meanflow` | MeanFlow (Geng et al., 2025): average velocity, MeanFlow identity with a JVP | 1–4 steps | same |

The flow models use MeanFlow's convention, `z_t = (1 - t) x + t eps`. Their network `u(z_t, t, h)` predicts the
average velocity over `[t - h, t]`, so FM, shortcut and MeanFlow differ only in their targets. The interval `h` is
fed through one extra Fourier embedding added to the U-Net's conditioning. That is the only architectural
difference from EDM (+0 parameters, since the embedding is a fixed random feature).

Options on top of MeanFlow (`config/agent/denoiser/_flow.yaml`, `config/trainer.yaml`):

- **Self-forcing-style training** (`denoiser.training.self_forcing`). For a fraction of the batch, the context frames
  before the target are generated by the model itself, with cheap 1-step rollouts from ground-truth context. Targets
  stay ground truth.
- **GameNGen-style context noise augmentation** (`context_noise_max`). Gaussian noise is added to the context frames,
  and the noise level is given to the network. This is the comparison point for self-forcing.
- **x-prediction / x-space loss** (`parameterization: x`, `loss_space: x`). The network outputs a clean frame
  (`u = (z_t - x) / t`), and the error can be measured on frames instead of velocities. Dreamer 4 reports that its
  x-space loss roughly halved FVD.
- Exact JVP (`jvp: autograd`, `torch.func.jvp`) or a cheaper finite-difference JVP (`jvp: finite_difference`).

## Experiments (`+experiment=...`)

World-model-only training on a fixed dataset per game. The datasets are collected once, with DIAMOND's pretrained
Atari agents playing epsilon-greedy (`src/collect_dataset.py`). Each run is 100k updates at batch size 32, with an
EMA of the weights used for evaluation.

| Experiment | What |
|---|---|
| `wm_edm` | EDM, evaluated at 1 and 3 steps |
| `wm_fm` | Flow matching, evaluated at 1, 2, 4 and 8 Euler steps |
| `wm_shortcut` | Shortcut model, evaluated at 1, 2, 4 and 8 steps |
| `wm_meanflow` | MeanFlow, evaluated at 1, 2 and 4 steps |
| `wm_meanflow_xpred` | MeanFlow with x-prediction and x-space loss |
| `wm_meanflow_selfforcing` | MeanFlow trained on self-generated context (50% of samples, 4 frames, after 20k updates) |
| `wm_meanflow_ctxnoise` | MeanFlow with GameNGen-style context noise augmentation |

Evaluation (`src/eval_wm.py`), on held-out test episodes:

- **Next-frame quality** from ground-truth context: PSNR, SSIM and LPIPS, for each number of sampling steps.
- **Long rollouts** with the recorded actions: PSNR, SSIM and LPIPS vs rollout step, up to 300 frames (configurable).
- **Action responsiveness**, two ways. Genie's ΔPSNR compares rollouts with the real actions against rollouts with
  random actions, from the same start and the same noise. An inverse dynamics model (`src/train_idm.py`) checks
  whether it can recover the commanded actions from the generated frames (MineWorld-style), with its accuracy on
  real frames as the reference.
- **Speed**: ms per frame and FPS at batch size 1.

`scripts/aggregate_results.py` turns the evaluations into tables and figures.

## Running

On a Slurm cluster (scripts written for Virginia Tech ARC): edit `scripts/arc/config.sh`, build the environment as
described at the top of `scripts/arc/setup_env.sh`, then run `bash scripts/arc/submit_all.sh`.

Locally (Linux; on Windows, run `src/main.py` by its absolute path):

```bash
pip install -r requirements.txt
python src/collect_dataset.py --game Boxing --out-dir data/Boxing
python src/train_idm.py --data-dir data/Boxing --out idm/Boxing/idm.pt
python src/main.py +experiment=wm_meanflow env.train.id=BoxingNoFrameskip-v4 \
    static_dataset.path=$PWD/data/Boxing hydra.run.dir=runs/wm_meanflow/Boxing/seed1 common.seed=1
python src/eval_wm.py --run-dir runs/wm_meanflow/Boxing/seed1 --data-dir data/Boxing --idm idm/Boxing/idm.pt --name test_ema
python scripts/aggregate_results.py --runs-root runs --out results
```

A MeanFlow world model can also be used in DIAMOND's full RL loop (agent trained in imagination with 1-step
sampling): `python src/main.py agent/denoiser=meanflow sampler=flow world_model_env.diffusion_sampler.num_steps=1`.

<a name="try"></a>
## [⬆️](#quick_links) Try our playable diffusion world models

```bash
python src/play.py --pretrained
```

Then select a game, and world model and policy pretrained on Atari 100k will be downloaded from our [repository on Hugging Face Hub 🤗](https://huggingface.co/eloialonso/diamond) and cached on your machine.

Some things you might want to try:
- Press `m` to change the policy between the agent and human (the policy is playing by default).
- Press `↑/↓` to change the imagination horizon (default is 50 for playing).

To adjust the sampling parameters (number of denoising steps, stochasticity, order, etc) of the trained diffusion world model, for instance to trade off sampling speed and quality, edit the section `world_model_env.diffusion_sampler` in the file `config/trainer.yaml`.

See [Visualization](#visualization) for more details about the available commands and options.

<a name="launch"></a>
## [⬆️](#quick_links) Launch a training run

To train with the hyperparameters used in the paper on cuda:0, launch:
```bash
python src/main.py env.train.id=BreakoutNoFrameskip-v4 common.devices=0
```

This creates a new folder for your run, located in `outputs/YYYY-MM-DD/hh-mm-ss/`.

To resume a run that crashed, navigate to the fun folder and launch:

```bash
./scripts/resume.sh
```

<a name="configuration"></a>
## [⬆️](#quick_links) Configuration

We use [Hydra](https://github.com/facebookresearch/hydra) for configuration management.

All configuration files are located in the `config` folder:

- `config/trainer.yaml`: main configuration file.
- `config/agent/default.yaml`: architecture hyperparameters.
- `config/env/atari.yaml`: environment hyperparameters.

You can turn on logging to [weights & biases](https://wandb.ai) in the `wandb` section of `config/trainer.yaml`.

Set `training.model_free=true` in the file `config/trainer.yaml` to "unplug" the world model and perform standard model-free reinforcement learning.

<a name="visualization"></a>
## [⬆️](#quick_links) Visualization

<a name="play_mode"></a>
### [⬆️](#quick_links) Play mode (default)

To visualize your last checkpoint, launch **from the run folder**:

```bash
python src/play.py
```

By default, you visualize the policy playing in the world model. To play yourself, or switch to the real environment, use the controls described below.

```txt
Controls (play mode)

(Game-specific commands will be printed on start up)

⏎   : reset environment

m   : switch controller (policy/human)
↑/↓ : imagination horizon (+1/-1)
←/→ : next environment [world model ←→ real env (test) ←→ real env (train)]

.   : pause/unpause
e   : step-by-step (when paused)
```

Add `-r` to toggle "recording mode" (works only in play mode). Every completed episode will be saved in `dataset/rec_<env_name>_<controller>`. For instance:

- `dataset/rec_wm_π`: Policy playing in world model.
- `dataset/rec_wm_H`: Human playing in world model.
- `dataset/rec_test_H`: Human playing in test real environment.

You can then use the "dataset mode" described in the next section to replay the stored episodes.

<a name="dataset_mode"></a>
### [⬆️](#quick_links) Dataset mode (add `-d`)

**In the run folder**, to visualize the datasets contained in the `dataset` subfolder, add `-d` to switch to "dataset mode":

```bash
python src/play.py -d
```

You can use the controls described below to navigate the datasets and episodes.

```txt
Controls (dataset mode)

m   : next dataset (if multiple datasets, like recordings, etc)
↑/↓ : next/previous episode
←/→ : next/previous timestep in episodes
PgUp: +10 timesteps
PgDn: -10 timesteps
⏎   : back to first timestep
```

<a name="other_options"></a>
### [⬆️](#quick_links) Other options, common to play/dataset modes

```txt
--fps FPS             Target frame rate (default 15).
--size SIZE           Window size (default 800).
--no-header           Remove header.
```

Each new run is located at `outputs/YYYY-MM-DD/hh-mm-ss/`. This folder is structured as follows:

```txt

│
└─── checkpoints

│   │
│   └─── agent_versions
│       │   ...

│       │   agent_epoch_01000.pt  # agent weights only
│
└─── config
│   |   trainer.yaml
|
└─── dataset
│   │
│   └─── train
│   |   │   info.pt
│   |   │   ...
|   |
│   └─── test
│       │   info.pt
│       │   ...
│
└─── scripts
│   │   resume.sh
|   |   ...
|
└─── src
|   |   main.py
|   |   ...

└─── wandb
    |   ...
```
